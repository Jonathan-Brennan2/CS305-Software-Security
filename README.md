# CS305-Software-Security

This repository contains my comprehensive security assessment and refactoring work for Artemis Financial, a financial consulting firm that manages highly sensitive client data like retirement plans, investments, and insurance details. The primary goal of this assignment was to modernize an older, vulnerable REST API originally deployed on an outdated JavaSE-1.8 runtime environment, protecting it against destructive network vectors like Man-in-the-Middle (MitM) sniffing, credential stuffing, and injection attacks. To execute this, I implemented a robust defense-in-depth architecture across multiple key layers. I successfully eliminated hardcoded database credentials by refactoring the system to utilize secure runtime environment variables, updated the unencrypted JDBC connection string to mandate transport-layer encryption, and enforced strict authentication rules via Spring Security. Additionally, I converted loose, open-ended request routes into single-purpose HTTP verb endpoints and integrated structural input validation boundaries to sanitize incoming parameters before they could reach our application logic.
Conducting this vulnerability assessment highlighted both the severe business risks of insecure coding and the immense value that a proactive security culture brings to an organization. Writing code securely stops exploits before they can ever reach production, which saves companies from devastating financial fraud, catastrophic data leaks, and severe legal fines stemming from global compliance standards like GLBA, PCI-DSS, or GDPR. The most challenging yet helpful part of this project was manually combing through the source controllers and database connection configurations. It was eye-opening to see how standard development shortcuts—such as leaving administrative "root" accounts active or using raw e.printStackTrace() commands for quick debugging—inadvertently hand attackers a detailed structural roadmap of the system internals. To verify that my security modifications did not break core system functionality or introduce regressions, I utilized Apache Maven to build the application and execute core test suites, followed by a secondary automated regression scan using the OWASP Dependency-Check Maven plugin to ensure the patched libraries didn't introduce new conflicts.
This project serves as a practical showcase for future employers of my ability to take a legacy, insecure codebase, perform a full vulnerability analysis, and implement modern mitigation strategies. Through this work, I demonstrated how to successfully identify and remediate deep framework-level flaws, specifically targeting and patching critical vulnerabilities like the CVE-2022-22965 Spring4Shell Remote Code Execution exploit by updating parent build configurations. Moving forward, I plan to integrate automated Static Application Security Testing (SAST) pipelines directly into my continuous integration workflows, track emerging exploits via the National Vulnerability Database (NVD), and leverage the OWASP Top 10 framework to continuously evaluate security postures. Ultimately, this assignment proves my capacity to balance operational business software requirements with strict data security best practices, delivering an enterprise-ready product aligned with modern compliance expectations.
